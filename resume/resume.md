# Kabir Kenth — résumé source

The PDF is generated by `build.py`, not from this file. This is the readable mirror.
Edit `build.py`, run `sh resume/build.sh` (or Cmd+Shift+B in VS Code), and it rewrites
`Kabir-Kenth-Resume.pdf` in place. The editing guide is at the top of `build.py`.

Constraints baked into `build.py`: one page, Letter, single column, base-14 Helvetica,
no tables or images, plain `|` separators, plain hyphens in dates, job title on its own
line above the company. All of that is there so a resume parser reads it correctly.

## PROJECTS

**ApplyTron: LLM Job Application Platform**
Live at app.kabirkenth.me | 2026 | Next.js, TypeScript, Supabase, Claude API, Playwright, Vitest, Railway
- Ingests job listings, scores each one against a parsed resume with the Claude API, and generates a tailored ATS-safe PDF through react-pdf. Multi-user and authenticated.
- No document reaches an employer without a person approving it first. The gate is a guarded state machine sitting behind row-level security in Postgres.
- A Playwright worker on Railway fills and submits application forms, screenshotting each one for review before it submits. Vitest covers the security boundaries and the business rules.

**Market Sentiment Pipeline: News Sentiment and Graded Signals**
Live at market-sentiment-pipeline.vercel.app | 2026 | Python, PostgreSQL, Gemini, scikit-learn, Railway
- A weekday Railway cron job pulls prices and headlines for five stocks and scores the news with Gemini.
- Postgres upserts on natural keys skip unchanged rows, so a rerun changes 0 rows. Version one appended and double-counted.
- A Random Forest calls the next session, a SQL view grades each call against the next close, and a public dashboard shows the hit rate beside a naive baseline.

**FreightSwipe: Two-Sided Freight Matching Platform**
Live at freightswipe.vercel.app | 2025 - 2026 | React 19, Express, PostgreSQL, Prisma, Playwright, Vercel
- One load record that both sides read from, which removes the two-copy reconciliation I used to do by hand at Fortel. A load only reaches in-transit after the shipper and the trucker have each confirmed it.
- The React bundle and the Express API deploy as a single Vercel app so the auth cookie stays first-party: no SameSite=None, no CORS preflight, no second cold start.
- A read-only Playwright smoke suite signs in as each role and checks that all 16 routes actually render, not just return 200. It exits non-zero, so a blank page blocks the merge.

### Sep 22 2026 — formatting pass

- **Earlier Experience** now has its own heading with one position per line (newest first),
  instead of three positions run together on a line that wrapped mid-entry.
- **Skills** lines only wrap between items, so no skill is split across two lines and no item
  is left alone on a line.
- Spacing tightened by fractions of a point (role and section gaps, bullet spacing, top and bottom
  margins) to keep everything on one page with the extra lines.
- `build.py` now has an editing guide at the top, escapes a plain `&` automatically, and reports
  the space left on the page after each build, warning if it spills to a second page.

**FreightSwipe was the stale entry.** It was dated `2025`, carried no URL, and described a
JWT-authenticated REST API with role dashboards. Since then the repo shipped a live Vercel

testing strategy, and migrated address entry to `PlaceAutocompleteElement`. All three bullets

- The live URL is now in the header line, the way ApplyTron's is. Dated `2025 - 2026`.
- The dual-confirmation rule (`shipperInTransitConfirmed` **and** `truckerInTransitConfirmed`
